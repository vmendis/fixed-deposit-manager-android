2. Roles

  • Architect (arena.ai Agent Mode): writes tests, owns assertions, writes app code + spec, pushes the session branch, triages reports
  • Executor (Roo): Windows 11, Android Studio, AVD Pixel_7_API_34 API 34 — runs commands, collects evidence, writes report. Never edits app code, never invents selectors
  • Reviewer (vmendis): submits report to architect, UX sign-off, merges PR

The split — permanent (established 2026-10-25, tested)

The GitHub App behind this chat holds issues: read and no projects scope. The agent can create an issue and can never edit, comment on, close or delete one. It cannot move a card or set a field. Adding a collaborator, pasting a PAT, or opening a new chat changes nothing — the agent already authenticates as the repo owner and is still capped. Only Arena can raise this, by changing the App manifest.

The owner's part is not "a few clicks". Every action has a body of text attached, and producing that text is the agent's job. A handoff without the text is an incomplete handoff.

Branch lifecycle

  • Session branch = where fixes land and where tests run. Named by the Arena session
  • dev = integration branch. Receives merges only, never tested mid-round
  • Never merge before a green report exists for that exact commit
  • After the feature PR merges → downstream dev→master handling proceeds as before; no long-lived dev between features
  • master is never deleted. Instruction files DO ship to master — see §5b

Selector contract (do not invent)

  • testTag("bankMonogram"), summary:<bank> e.g. summary:NSB
  • Visible text: fdNumber NSB-78412, words Rs 1 Million, exact Rs 1,000,000.00, payout Monthly payout / At maturity, chips Active / Matured
  • contentDescription: Add FD, Back, Edit, Sort, Recycle bin, Maturing soon, More actions
  • Dialog: dialogConfirm / dialogDismiss — use confirmDialog() helper
  • Settings rows live in a verticalScroll Column that composes every child — so assert on semantics-tree existence, never on assertIsDisplayed(). Scroll only before a click
  • If missing: record SELECTOR-MISSING, do not edit app code

3. Commands — bash (MINGW64) only

Shell rule: grep, ls, ./gradlew, mkdir, sleep, cat. Never chcp, findstr, dir, gradlew.bat, if not exist, timeout /t. Verify with bash --version | head -1.

Never swap in a Windows tool when a bash command fails. chcp → does not exist here. findstr → grep -n. dir/type/copy/del/where/timeout /t → ls/cat/cp/rm/command -v/sleep. A failed findstr printing Cannot open is noise, not a failed gate — the gate is the grep -q ... && echo line. Report a failure; never retry it with another tool.

Never wrap a command in bash -c "...". The wrapper expands $VAR and nested quotes before bash parses them, so echo $BASH_VERSION arrives as echo 5.3.9(1)-release and dies on the unparenthesised token: 
bash: -c: line 1: syntax error near unexpected token `('
bash: -c: line 1: `echo 5.3.9(1)-release'
Type into the MINGW64 prompt directly. Any command Roo wraps must contain no $ and no nested double quotes.

5. Report spec — TEST-REPORT-V<N>.md

ARTIFACTS ARE REQUIRED. A round produces test-artifacts-<issue>/ (the folder carries the issue number — test-artifacts-5 for #5) with logcat.txt + 4 screenshots, app foreground, plus the report. No artifacts = untriageable: without the XML <failure> block nobody can see which line failed, and the round stalls on guesswork. That happened three times on 2026-10-24. 
# TEST REPORT — V<N>
- Branch / commit: <session branch> @ <git rev-parse --short HEAD>   <-- MANDATORY
- Environment: Windows 11, Android Studio <ver>, AVD Pixel_7_API_34 / API 34,
  Gradle 8.13, AGP 8.13.2, Kotlin 2.0.20, JDK 17.0.16
- Tiers executed: 2 / 2

## Tier1 (95)   | Test class | Tests | Passed | Failed | Duration | Report path |
## Tier2 (38)   | Test class | Tests | Passed | Failed | Duration | Report path |

## Evidence of GREEN  (real logcat, real png)
## Failures          (verbatim message + <=30 logcat + XML 3-10 lines incl. "...(Test.kt:NN)")
## Blockers          (SELECTOR-MISSING)
## Not covered
REJECTED if: no branch/SHA; literal $(...) or (unknown); guessed versions; Tier1 not 95 or Tier2 not 38; durations summed; "see logcat" placeholders; no Test.kt:NN frame in a failure section; launcher screenshots; no --rerun-tasks; gates unchecked; artifacts in repo root; executor edited app code.

5b. Instruction files — permanent, numbered, committed

One file per issue, under docs/test-instructions/, zero-padded to three digits so they sort correctly forever.

docs/test-instructions/
  TEST-INSTRUCTIONS-005.md     issue #5
  TEST-INSTRUCTIONS-006.md     issue #6
  TEST-INSTRUCTIONS-010.md     issue #10   <- sorts after 005, not before
RuleWhy
Committed and pushed — never deleted before merge A file that lives only on a branch is a file Roo cannot find. That failure already cost a round
Pad to 3 digits: 005, not 5 Unpadded, -5.md sorts after -11.md
The name carries the issue numberMatches the artifact folder test-artifacts-005/
Read from the branch under test, after syncing it The committed copy at that SHA is the one that matches the code
Roo's prompt is now: Open docs/test-instructions/TEST-INSTRUCTIONS-005.md and follow it
Retired 2026-10-25: "TEST-INSTRUCTIONS.md on the test branch only; removed before final merge."

6. Merge gate — after GREEN

  • A green report exists for that exact SHA — non-negotiable
  • Instruction file for this issue is committed and present — it is never removed before merge
  • Spec both copies byte-identical
  • No open CODE-BUGs
  • UX sign-off on app screenshots (not launcher)
  • git ls-remote SHA matches local

6b. Issue ↔ PR linking — how an issue closes itself

Issues live in roadmap (vmendis/fd-manager-roadmap). PRs live in the code repo (fixed-deposit-manager-android). Three conditions, all of which must hold.

Condition 2 fails silently. GitHub docs, verbatim:
"The special keywords in a pull request description are interpreted only when the pull request targets the repository's default branch. If the pull request targets any other branch, then these keywords are ignored, no links are created, and merging the PR has no effect on the issues."
The code repo's default branch is master. Feature PRs target dev. A Closes line on a feature PR therefore does nothing — and raises no error.
ConditionRequirement
1 — syntaxcross-repo form is mandatory: Closes vmendis/fd-manager-roadmap#N. A bare Closes #N looks for that issue in the code repo and finds nothing
2 — base branchthe PR must target master — i.e. the dev→master promotion PR, never the feature PR
3 — mergemerged, not closed. Closing a PR without merging closes nothing
PRBaseLine to writeCloses?
Feature / arenadevRefs vmendis/fd-manager-roadmap#NNo
PromotionmasterCloses vmendis/fd-manager-roadmap#N — one keyword per issueYes

Closes a#1, b#2 closes only the first. Repeat the keyword for every reference.

Then the chain finishes itself: merge → issue closes → Project workflow sets Status = Done. The project's built-in Item closed → Done workflow is on by default.
